Доставка Новою Поштою для WooCommerce: без розрахунку вартості на чекауті (лише вибір відділення/адреси),
ручне створення ЕН з картки замовлення, автоматичний періодичний моніторинг статусів ЕН
та гнучкі правила автоматизації (нотатки, зміна статусу замовлення, вебхуки).

== Опис ==

**Доставка**
* Метод доставки "Нова Пошта" для зон доставки WooCommerce.
* 4 варіанти сервісу: склад-склад, склад-двері, двері-склад, двері-двері.
* Вартість доставки на чекауті не показується й не додається до замовлення — рахується вручну в адмінці, де вже відома фактична вага.
* Предиктивний пошук міста, відділення/поштомату та вулиці прямо на чекауті.

**Експрес-накладні (ЕН/ТТН)**
* Ручне створення ЕН з картки замовлення (WooCommerce HPOS сумісно).
* Підтримка всіх 4 типів сервісу.
* Історія створених ЕН на картці замовлення з посиланням на трекінг.

**Моніторинг статусів**
* WP-Cron періодично опитує Nova Poshta API для всіх ЕН зі статусом, відмінним від "Отримано".
* Інтервал опитування налаштовується (хвилини).
* Кнопка ручного запуску перевірки "зараз" у налаштуваннях.

**Автоматизації**
* Конструктор правил: тригер = конкретний статус ЕН або "будь-яка зміна".
* Дії: додати нотатку до замовлення, змінити статус замовлення, надіслати вебхук (JSON POST) з повними даними замовлення.
* Журнал виконаних дій з результатом (ok/error).

== Встановлення ==

1. Завантажте архів плагіна через Плагіни → Додати новий → Завантажити плагін.
2. Активуйте плагін.
3. Перейдіть у WooCommerce → Nova Express і вкажіть API-ключ та дані відправника.
4. Додайте метод доставки "Нова Пошта" у потрібній зоні доставки (WooCommerce → Налаштування → Доставка).

= 1.10.9 =
* Виправлено рідкісні "пропущені" вебхуки/email автоматизації: раніше вони відправлялись синхронно в тому самому запиті, що й створення/оновлення ТТН — після кількох послідовних викликів Nova Poshta API (контрагент, ТТН, опитування статусу) на хостингах із типовим лімітом виконання (~30с) процес міг обриватись саме на відправці вебхука, вже ПІСЛЯ того, як ТТН успішно створилась і зберіглась — без жодної помилки в журналі. Тепер відправка вебхука/email виконується окремою фоновою подією (WP-Cron), не залежною від часу виконання основного запиту.
* Синхронізація довідника відділень пришвидшена: розмір сторінки збільшено з 150 до 500 записів (максимум, який приймає API), пауза між сторінками зменшена з 900мс до 300мс, а запис у базу даних тепер відбувається одним запитом на всю сторінку замість окремого запиту на кожен рядок. Разом це в кілька разів скорочує загальний час повної синхронізації (десятки тисяч відділень).

= 1.10.8 =
* Виправлено незрозумілу помилку Нової Пошти «Max param value sizes is …» при створенні ЕН: тепер плагін зберігає реальні ліміти габаритів кожного відділення/поштомата (SendingLimitationsOnDimensions з довідника НП — у поштоматів комірки різного розміру, часто значно менші за загальний запобіжник 120 см) і перевіряє габарити місця ЩЕ ДО відправки запиту в API. Якщо посилка не влазить — плагін одразу пише зрозумілою мовою, яка сторона завелика і на скільки, замість загадкового технічного тексту від НП.
* Якщо ця (чи схожа технічна) помилка все ж прийде безпосередньо від API — до її тексту тепер додається пояснення простою мовою, а не лишається лише оригінальний технічний рядок.

* Виправлено критичний баг: на сторінці автоматизацій нееекранований апостроф у JSON-атрибуті ламав розмітку сторінки, через що кнопка "+ Нове правило" (і все, що йшло після неї в DOM) переставало працювати.
* Прибрано технічні поля "Ref" з інтерфейсу налаштувань відправника — тепер лише ПІБ і телефон; Ref обчислюється й зберігається плагіном автоматично через Nova Poshta API як при кнопці "Отримати автоматично", так і при звичайному ручному введенні + збереженні форми.
* Один активний ТТН на замовлення: кнопки "Створити"/"Додати" ховаються, коли ТТН вже є; з'являються знову лише після видалення.
* Автоматичне виявлення видаленого на боці Нової Пошти ТТН (як під час планового опитування, так і вручну кнопкою "Оновити статус зараз") — картка прибирається з замовлення, з'являються кнопки створення знову.
* Більше інформації в блоці замовлення: код статусу, тип доставки, час останньої перевірки.
* Кастомні плейсхолдери в шаблонах опису/додаткової інформації: {meta:ключ_поля} — будь-яке довільне мета-поле замовлення.
* Усі користувацькі тексти в інтерфейсі перейменовано з "ЕН" на "ТТН".

= 1.4.0 =
* Виправлено: помилки збереження/видалення правил автоматизації тепер повертають реальний текст помилки БД замість "тихого" провалу.
* Додано видалення ЕН повністю з бази (з боку Нової Пошти — best-effort, і з локальної таблиці) прямо з картки замовлення.
* Одразу після створення/додавання ЕН плагін опитує реальний статус (замість очікування наступного циклу крону).
* Опис та додаткова інформація відправлення тепер налаштовуються шаблонами з плейсхолдерами ({order_number}, {site_name}, {customer_name} тощо).
* Пояснення терміну "Ref" прямо в інтерфейсі налаштувань.
* Покращено дизайн кнопки створення ЕН та вибір типу дії автоматизації (замість системного prompt).

= 1.3.0 =
* Виправлено критичний баг: селект відділення відправника на сторінці налаштувань не підвантажувався при відкритті сторінки (лише після ручного пошуку міста), через що поле sender_warehouse_ref затиралось порожнім значенням при кожному збереженні. Це і було справжньою причиною "Sender is incorrect; ContactSender is incorrect".
* Захист від випадкового стирання: форма більше не затирає sender_warehouse_ref порожнім значенням, якщо в POST його не було.
* Картка відправника на сторінці створення ЕН тепер показує ім'я контактної особи, телефон і людську назву відділення замість сирого Ref.
